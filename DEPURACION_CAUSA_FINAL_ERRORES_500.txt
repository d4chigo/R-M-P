================================================================================
INVESTIGACIÓN A FONDO
================================================================================

Problema: Los errores 500 persistían aunque:
1. Las queries SQL eran correctas
2. logAudit() estaba dentro del try-catch
3. Los datos SÍ se guardaban (se veían al refrescar)

Pregunta: ¿QUÉ estaba mandando el error 500?

Respuesta: Una DOBLE RESPUESTA HTTP

================================================================================
CAUSA RAÍZ: DOUBLE RESPONSE BUG
================================================================================

El problema era que había MÚLTIPLES res.json() siendo llamados:

┌──────────────────────────────────────────────────────────────┐
│ ESTRUCTURA DEL CÓDIGO (ANTES):                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ const deleteTesoreria = async (req, res) => {               │
│   try {                                                     │
│     // ... validaciones ...                                │
│     const connection = await db.getConnection()             │
│     try {                                                   │
│       await connection.beginTransaction()                   │
│       // ... queries ...                                    │
│       try {                                                │
│         await logAudit(...)                                │
│       } catch (e) {}                                       │
│       await connection.commit()              ← ✅ COMMIT   │
│     } catch (txErr) {                                      │
│       await connection.rollback()                          │
│       return res.status(500).json(...)  ← RESPUESTA 1      │
│     } finally {                                            │
│       connection.release()                                 │
│     }                                                       │
│                                                              │
│     res.json({...})  ← ⚠️ RESPUESTA 2                       │
│                                                              │
│   } catch (error) {                                        │
│     res.status(500).json(...)  ← ⚠️ RESPUESTA 3 (SIN RETURN)│
│   }                                                         │
│ }                                                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘

PROBLEMA:
- Si las queries OK → commit() OK → sale del try interior
- PERO sigue ejecutando código FUERA del try interior
- Ejecuta res.json({...}) ← RESPUESTA 2
- Si algo sale mal AQUÍ (ej: res ya envió headers) → excepción
- El catch exterior ATRAPA la excepción
- Intenta enviar res.status(500).json(...) ← RESPUESTA 3
- Express dice "ya envié headers" → Error 500

RESULTADO:
✅ Datos guardados (commit fue exitoso)
❌ Cliente recibe error 500 (por intento de doble respuesta)

================================================================================
LA VERDADERA SOLUCIÓN
================================================================================

Usar `return` en TODAS las respuestas. Así garantizamos que solo 
una respuesta se envía:

┌──────────────────────────────────────────────────────────────┐
│ ESTRUCTURA CORRECTA (DESPUÉS):                               │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ const deleteTesoreria = async (req, res) => {               │
│   try {                                                     │
│     // ... validaciones ...                                │
│     const connection = await db.getConnection()             │
│     try {                                                   │
│       await connection.beginTransaction()                   │
│       // ... queries ...                                    │
│       try {                                                │
│         await logAudit(...)                                │
│       } catch (e) {}                                       │
│       await connection.commit()                            │
│       return res.json({...})  ← ✅ RETURN = FIN            │
│     } catch (txErr) {                                      │
│       await connection.rollback()                          │
│       return res.status(500).json(...)  ← ✅ RETURN = FIN  │
│     } finally {                                            │
│       connection.release()                                 │
│     }                                                       │
│     // Aquí NUNCA se llega (por los return)                 │
│                                                              │
│   } catch (error) {                                        │
│     return res.status(500).json(...)  ← ✅ RETURN = FIN    │
│   }                                                         │
│ }                                                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘

MEJORA:
✅ Cada rama de código tiene exactamente UNA respuesta
✅ Cada respuesta usa `return` para detener ejecución
✅ Nunca hay doble respuesta
✅ Nunca hay intentos de res.json() después de que ya se envió headers

================================================================================
POR QUÉ ESTO FIX EL ERROR 500
================================================================================

ANTES:
1. Transacción OK
2. commit() OK
3. Intenta res.json({...}) PRIMERA VEZ
4. Si eso falla por cualquier razón → excepción
5. catch exterior ATRAPA → intenta res.status(500).json() SEGUNDA VEZ
6. Express rechaza → Error 500 al cliente

DESPUÉS:
1. Transacción OK
2. commit() OK
3. `return res.json({...})` ← Una respuesta, punto final
4. Si por algún motivo se lanza excepción antes de return:
   - catch exterior la atrapa
   - `return res.status(500).json(...)` ← Una respuesta, punto final
5. NUNCA hay intento de doble respuesta
6. Cliente recibe siempre UNA respuesta válida

================================================================================
BEST PRACTICE: SIEMPRE USAR RETURN EN res.json()
================================================================================

❌ INCORRECTO:
  res.json({ success: true });
  // Código después de res.json() que PUEDE ejecutarse si hay async pendientes

✅ CORRECTO:
  return res.json({ success: true });
  // Código NUNCA se ejecuta después

En Express, es práctica estándar usar `return res.json()` para:
1. Detener ejecución inmediata
2. Evitar múltiples respuestas
3. Prevenir race conditions
4. Mejorar rendimiento

================================================================================
PATRÓN CORRECTO PARA FUNCIONES ASYNC HANDLER
================================================================================

const myHandler = async (req, res) => {
  try {
    // Validaciones
    if (!valid) {
      return res.status(400).json({ error: "..." });  // ← RETURN
    }
    
    // Lógica
    const result = await doSomething();
    
    // Respuesta exitosa
    return res.json({ success: true, data: result });  // ← RETURN
    
  } catch (error) {
    // Error handling
    console.error("Error:", error);
    return res.status(500).json({ error: error.message });  // ← RETURN
  }
};

Regla: SIEMPRE hay exactamente UNA respuesta por rama de código.

RESUMEN DEL JOURNEY DE DEBUGGING
================================================================================

1. Síntoma: Error 500 pero datos guardados
   → Indicaba que la BD SÍ guardaba (commit exitoso)
   → Pero el cliente recibía error (problema en respuesta HTTP)

2. Primer intento: Arreglar SQL
   → Cambié getLimaNowSQLClause() por CURRENT_TIMESTAMP
   → No solucionó el problema

3. Segundo intento: Proteger logAudit()
   → Moví logAudit() dentro del try-catch
   → No solucionó completamente

4. Investigación profunda: ¿QUÉ está mandando 500?
   → Encontré que había código que ejecutaba DESPUÉS de res.json()
   → Cuando ese código fallaba, try-catch exterior lo atrapaba
   → Intentaba enviar SEGUNDA respuesta
   → Express: "Ya envié headers" → Error 500

5. Solución final: Usar return en TODAS las res
   → Un return por rama de código
   → Una respuesta garantizada

================================================================================
LECCIONES APRENDIDAS
================================================================================

✅ Siempre usar `return` cuando se envía respuesta HTTP
✅ Ser consciente de que código sigue ejecutando sin `return`
✅ En async handlers, cada rama debe tener UN ÚNICO punto de salida
✅ Los datos guardarse ≠ respuesta OK al cliente (son procesos separados)
✅ Debugging: si los datos guardan pero hay error 500 → revisar respuestas HTTP

CONCLUSIÓN

El problema NO era de lógica de BD ni de SQL.
Era de control de flujo en Express: doble respuesta HTTP.

Una simple línea: agregar `return` en res.json()
Lo que parecía complejo resultó ser un error simple de programación.
